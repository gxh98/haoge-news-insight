# 边界情况与失败模式

常规新闻按 `SKILL.md` 走即可。这份文件处理"这条新闻有点怪"的情况。

## 一、取不到 / 取不全

| 症状 | 处理 |
|---|---|
| 付费墙、需登录、反爬 | 换搜索找 **≥2 家**同题报道，交叉核对，**只写各家一致的部分**；末尾加 `> 原文未能直接访问，基于 N 家转载交叉核对` |
| 抓到的是 JS 空壳页面 | 换移动版域名（`m.` 前缀）或用搜索找转载；仍失败则按上一条 |
| 链接 404 / 已删除 | 用标题搜索存档或转载；找不到就**如实说明并请用户粘贴正文** |
| 视频 / 播客 / 直播回放 | 只取标题 + 简介，**降级输出**；末尾注明"仅凭标题与简介，信息不足以给可靠洞见" |
| 只有标题（快讯、推送通知） | 走"短讯模式"：核心梳理 2 条、洞见保守；末尾注明"仅有标题" |

**共同底线：取不到就说取不到。编造一条新闻的代价，远大于这次没提炼成。**

## 二、正文噪音

中文门户页面往往**正文只有几百字，其余全是"为你推荐"**。三条防线：

1. 正文边界 = 标题第一次出现 → "责任编辑 / END / 免责声明 / 相关推荐"之间。
2. 页面里重复出现的其他新闻标题（尤其是带缩略图的一串），**是推荐位**，不是本条内容。
3. 若不确定某段是不是正文，问自己：这段在讲本条新闻的主语吗？不是，就丢。

## 三、观点文 / 评论（不是事实报道）

- 判断：通篇是作者的判断和主张，缺少可核验的事件与数字。
- 处理：【原文标题】后标 `（观点文）`；**作者的立场是事实的一部分，要如实呈现，但不等于你的洞见**。
- 三条洞见必须与作者立场分离：作者说"行业将崩盘"，你的洞见不能只是把他的判断换个说法。
- 【1个核心词】取观点本身（如 `算力过剩`），不要取情绪。

## 四、多事件新闻（早报、快讯合集）

- 典型：`AMD拟收购李飞飞公司；长鑫官宣349亿元投资丨新鲜早科技`
- 处理：**以标题的主语 + 动作为唯一主线**，其余条目完全不写。
- 若用户明确想要全部条目，则**每条各出一张卡片**，不要揉成一张。
- 【原文标题】仍照抄完整标题（含副标题），不要截断。

## 五、标题与正文不符（标题党）

- 处理：【原文标题】照抄（那是原文事实），但**事实层以正文为准**。
- 若正文根本没有标题暗示的事件：在末尾注明 `> 注：正文未支持标题所述内容`，【核心梳理】只写正文实际说了什么。
- 这种情况往往本身就是好洞见——"标题与内容的偏离"是一种可复用的传播机制。

## 六、数据密集（财报、论文、指数）

- 只挑**最有信息量的 1–2 个数字**进核心梳理，不要把全文数字搬进来。
- 数字必须带口径（同比/环比、季度/全年、美元/人民币），否则不写。
- 【1个底层规律】优先挂靠"指标与激励""预期与定价"类机制。

## 七、外文新闻

- 输出语言**跟随用户提问的语言**（默认中文）。
- 【原文标题】保留**原文语言**，不要翻译；可在末尾加一句中文对照。
- 专有名词用通用译名，不确定就保留原文。

## 八、未被证实 / 传闻

- 若原文本身用的是"据称""有消息称""传闻"，**必须原样保留这层不确定性**，不许写成既成事实。
- 末尾注明 `> 注：原文为未证实消息`。
- 这类新闻的洞见价值通常在"为什么会有人放这个消息"，而不是消息本身。

## 九、同一事件多家报道

- 优先选**信息量最大的一家**作为原文来源；用其他家补细节时必须能对上。
- 末尾只写你实际用的那家的链接与日期。
- 若几家互相矛盾，**如实写矛盾**，不要自行采信一方；末尾注明分歧点。

## 十、用户直接贴原文

- 跳过「取」，其余照走。【原文标题】用原文首行标题；没有标题就用内容概括一个，并注明"原标题缺失"。
- 结尾的溯源行改成 `> 来源：用户提供的原文｜<日期（若可知）>`。

## 十一、用户只发链接、不说别的

这是最常见的用法。**默认走完整流程**，不要反问"你想让我做什么"。
只有一种例外：链接内容完全无法获取 → 说明失败原因 + 请用户粘贴正文。

## 十二、用户一次发多条链接

- 默认：**逐条各出一张卡片**，卡片之间用分隔线隔开。
- 若超过 5 条，先问一句"要我全部出，还是先挑最重要的 3 条？"——避免输出淹没用户。
- 多条之间若存在关联（同一主题、同一趋势），可以在最后补一句"这几条的共同点"，但那不属于 7 字段，要明确标出来。
